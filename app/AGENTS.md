# AGENTS.md — task board app (`app/`)

Tool-agnostic baseline for any AI coding agent (Cursor, Claude Code, GitHub
Copilot, Codex, …) working inside `app/`. Detailed, verifiable rules live in
`.cursor/rules/*.mdc` at the repo root; this file is the shared summary.

## Stack

TypeScript 5.6 (strict, `noUncheckedIndexedAccess`), ESM (`"type": "module"`),
vitest 2.1. No framework, no UI, no build step — plain `.ts` modules.
Only two devDependencies: `typescript`, `vitest`.

## Structure

| Path | Role |
|---|---|
| `src/types.ts` | `Task`, `AppState`, `Filter`, `Action` union, `initialState` — **protected core** |
| `src/store.ts` | `createStore()` → `{ getState, dispatch, subscribe }` — **protected core** |
| `src/reducer.ts` | Pure `(state, action) => newState`; where the domain grows |
| `src/actions.ts` | Action creators (`addTask`, `toggleTask`, `removeTask`, `setFilter`) |
| `src/selectors.ts` | Pure read helpers (`visibleTasks`, `remainingCount`) |
| `src/lib/text.ts` | In-house text lib with a fixed API |
| `src/*.test.ts`, `src/lib/*.test.ts` | Colocated vitest tests |
| `src/index.ts` | Example wiring of the store |

## Commands

```bash
cd app
npm install         # once
npm test            # vitest run — must be green before you finish
npm run test:watch  # vitest in watch mode
npm run typecheck   # tsc --noEmit
```

**Lint is NOT configured** in this sample — there is no `npm run lint`. Do not
invent or add one; rely on `typecheck` + tests.

## Architecture

State is managed by a **custom in-house store** — deliberately NOT Redux,
Zustand, MobX or Jotai. Do not "modernize" it with a library.

- State changes happen **only** through `store.dispatch(action)`.
- Golden path to add behavior:
  1. add a variant to the `Action` union in `src/types.ts`;
  2. handle it in `src/reducer.ts` (return new objects/arrays);
  3. add an action creator in `src/actions.ts`;
  4. add a colocated `*.test.ts` (happy path + immutability).
- The reducer is pure: no I/O, no `Date.now()`/`Math.random()`/`fetch`; ids and
  timestamps are generated by the caller and passed in the payload.
- Writes go through action creators; derived reads go through selectors, not
  inline `state.tasks.filter(...)` in consumers.

## Code style

- **Named exports only** — no `export default`.
- **No `any`, `as any`, `@ts-ignore`, `@ts-expect-error`**, no `!` non-null
  assertions; handle `undefined` from index access explicitly (`tasks[0]?.done`).
- **Immutable updates**: spread / `map` / `filter`; never `push`, `splice`,
  `sort`, or assignment to state properties.
- Relative imports carry the `.js` extension (`from "./types.js"`); type-only
  imports use `import type`.
- Naming: files kebab-case, types/interfaces PascalCase, functions/variables
  camelCase, action types `domain/event` (`"task/added"`).
- Tests are colocated `<file>.test.ts`, vitest imported explicitly, AAA layout.

## `src/lib/text.ts` — fixed API

The entire supported surface is:

- `slugify(input: string): string`
- `truncate(input: string, maxLength: number, suffix?: string): string`
  (`maxLength` includes the suffix)
- `normalizeSpaces(input: string): string`

It is **not** lodash: `capitalize`, `camelCase`, `deburr` and friends **do not
exist**. Need one? Add it here as a named export with a test — never assume it.

## Guardrails

- **Do not edit `src/store.ts` or `src/types.ts` without explicit approval.**
  The only routine change to `types.ts` is *adding* an `Action` variant for a
  feature the user asked for; never change or remove existing members.
- Do not change the public signatures of `createStore`, the existing action
  creators, or the `lib/text.ts` functions — extend, don't rewrite.
- **No new dependencies** (`npm install <pkg>`) and no new tooling/config files
  (`eslint`, `prettier`, bundlers, `vitest.config.*`) without approval.
  Prefer the standard library and `lib/text.ts`.
- Do not relax `tsconfig.json` to make code compile — fix the code.
- Never commit secrets or real/NDA data; sample data here is synthetic on purpose.

## Definition of done

`cd app && npm test` and `npm run typecheck` are green, no protected file was
touched without approval, new behavior has a colocated test, and the change is
summarized (what changed and why) in the reply.
