# Cross-tool check (Task E — bonus)

**Інструменти:** Cursor (Agent mode) + Claude Code (Opus 5). Новий чат на кожен
прогін, жодних додаткових інструкцій у промпті.

**Два однакові промпти, по одному в кожен інструмент:**

- **P1 (тільки читання):** «Опиши конвенції цього проєкту: як тут можна змінювати
  стан, які файли захищені, чи можна додавати залежності. Нічого не змінюй.»
- **P2 (зі зміною коду):** «У демо `app/src/index.ts` заголовки задач треба
  показувати у Title Case («buy milk» → «Buy Milk»). Додай потрібний util і
  використай його.»

P2 вибраний навмисно: Task D перевірив `architecture` / `state-access` /
`do-not-touch` / `testing` / `conventions`, а `custom-lib.mdc` і
`dependencies.mdc` там не активувались. P2 б'є прямо в них — і навмисно **не
каже**, куди класти util. Пастка: спокуса створити новий файл, вписати інлайн
або потягнути lodash.

## Розбіжності

**1. Правила ті самі, механіка доставки різна.** У Cursor 5 із 7 `.mdc` мають
`alwaysApply: false` + `globs`, тобто правило приходить під файл, з яким агент
працює. У Claude Code всі 7 лежать у контексті наперед — у відповіді на P1 він
сам згадав деталь `custom-lib.mdc` («три функції, дефолтний суфікс "…" не
чіпати»), хоча промпт не торкався ні `app/src/lib/**`, ні `package.json`.
Результат однаковий, шлях — ні.

**2. Перелік джерел у Cursor — не повний аудит впливу.** На P1 Cursor написав
`it("lowercase sentence")` і «без beforeEach/snapshots». Ці формулювання є
тільки в `.cursor/rules/testing.mdc:20,25`; у `app/AGENTS.md` про `it()`,
`beforeEach` чи снапшоти немає нічого (grep чистий). Але `testing.mdc` у
переліку джерел відсутній. Правило вплинуло на відповідь, не потрапивши в
самозвіт.

**3. Семантика функції розійшлась — і кожен закріпив свою тестом.**

```ts
// Cursor:  .map((word) => word.charAt(0).toUpperCase() + word.slice(1).toLowerCase())
// Claude:  .map((word) => word.charAt(0).toUpperCase() + word.slice(1))
```

Cursor робить «справжній» Title Case і затирає регістр решти слова, що видно з
його ж тесту: `titleCase("  write   RULES ")` → `"Write Rules"`. Claude решту
слова не чіпає, і його тест це фіксує: `titleCase("write rules NOW")` →
`"Write Rules NOW"`. Контракти **взаємно несумісні** — функція Cursor провалила б
тест Claude (`"NOW"` стало б `"Now"`), і навпаки. Обидва прогони зелені, кожен у
власній версії. Правила про це не кажуть нічого, і це чесна межа rule-set'у:
він тримає архітектуру, а не продуктові рішення.

**4. Обсяг правки демо.** Обидва застосували `titleCase` на **читанні** —
у `console.log`, лишивши в стані сирий заголовок. Але Claude додатково
переписав вхідні дані демо (`addTask(buyMilk, "Buy Milk")` → `"buy milk"`), щоб
ефект було видно: `index.ts` +6/−6 проти +2/−2 у Cursor. Cursor обмежився рядком
виводу й імпортом. Жодне правило тут не порушене — це різниця в тому, наскільки
широко інструмент трактує «використай його».

**5. Гігієна коментарів — і тут Cursor краще.** Шапка `text.ts` каже «supported
surface is **exactly the three functions** below». Додавши четверту, Cursor
поправив і шапку:

```diff
-// exactly the three functions below with exactly these signatures. Do not
+// exactly the functions below with exactly these signatures. Do not
```

Claude функцію додав, а коментар лишив — тепер файл сам себе спростовує. Той
самий клас дефекту, що й застарілі числа в rule-set'і (нижче), і жодне правило
його не ловить: `custom-lib.mdc` вимагає jsdoc на **нову** функцію, але не
вимагає освіжити опис API.

**6. Застаріле число в baseline поїхало далі.** На P1 Cursor повторив «`npm test`
— 15 тестів, мають залишатися зеленими», бо так було написано в
`app/AGENTS.md:37,100`. Після Task D їх 20. Claude Code числа не називав.
Виправлено окремим комітом — разом з трьома verify-командами в
`architecture.mdc` / `testing.mdc`, які Task D теж зробив брехливими (чекали
«4 і 4» дій, 15 тестів у 3 файлах, 3 vitest-імпорти). Плюс `custom-lib.mdc`
вимагала **рівно три** експорти в `text.ts`, хоча сама ж дозволяє додавати —
обидва прогони Task E зробили дозволене, і перевірка впала б на правильній
роботі.

## Висновок

Baseline портативний: **обидва інструменти підхопили ті самі правила без
додаткової настройки і не порушили жодного** — util опинився в `text.ts` поруч
із сусідами, з перевикористанням `normalizeSpaces`, з тестами і без
залежностей; protected core не зачеплений, наявні тести не переписані, обидва
прогони зелені з чистим typecheck. Ціна портативності — два тонких
tool-специфічних файли-містки (`CLAUDE.md` з `@`-імпортами і `app/CLAUDE.md`),
які не дублюють правила, а лише вказують на них; без них Claude Code не побачив
би `.mdc` взагалі.

Найцінніше — де інструменти розійшлися: **не в дотриманні правил, а там, де
правил немає.** Семантика Title Case, обсяг правки демо і те, чи освіжити
коментар про API — три рішення, які rule-set не покриває, і в кожному два
інструменти обрали різне. Портативність правил не означає ідентичності
результату: правила звужують коридор, а не диктують крок.
